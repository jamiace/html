# 英文程度測驗（小一～高三）：設計與實作

> Purr Cozy 0.92.46（2026/11/06）。程式在 `js/placement.js`，文字在 `i18n/ui.json` 的 `pl.*`，後台分析在 `tools/admin.html`「學習分析 → 程度測驗」。

## 1. 玩家看到什麼

**搬家日（第一次）**。新玩家進到房間、房間載入完成約 1.5 秒後，會跳出「搬家日」視窗：貓咪把貼著英文標籤的紙箱推進來，有些標籤被雨淋糊了，請玩家幫忙辨認。玩家可以先選「你現在是幾年級」（也可以不說），然後開始拆箱：8～12 題，約 3 分鐘，題目會依作答自動調整難度。拆完後出現結果卡：年級徽章（例如「國小・小五」）、可能範圍（「大約落在 小四～小六」）、固定獎勵 60 金幣＋40 經驗，並送一張「英文程度獎狀」家具（可以掛在牆上，滑鼠移上去會顯示目前年級）。玩家按「下次再說」最多三次後就不再主動跳出，之後可以從「學習」視窗或「設定」自己開始。

**每日小測（之後每天）**。每日任務多一項「程度小測」（完成另給 30 金幣＋30 經驗）。點任務就直接開始，固定 8 題、約 1.5 分鐘，做完顯示「比上次進步了／和上次差不多／這次比較難」和新的年級。獎勵固定 10 金幣＋10 經驗，和答對幾題無關，所以故意答錯沒有好處。

**程度視窗**（學習視窗的第一列，或設定裡的卡片）。顯示目前年級徽章、可能範圍、測驗次數、和上次相比、第一次的年級、本週測了幾次、最近 40 次的成長曲線（線＝估計值，色帶＝±1 個標準誤），以及兩個設定：「名片上顯示程度：開／關」和「就讀年級」。

**名片**。開啟顯示時，名片上的名字旁邊會有一個年級標籤，其他玩家在排行榜、好友名片都看得到。關閉後立刻從雲端名片移除。

## 2. 模型

**量尺**：θ 是「年級」，1＝小一 … 12＝高三，小數有意義（5.4＝小五偏上）。

**題目難度**：每個字在 `vocab.js` 有建議年級 `g`（來自 `tools/vocab.json` 的 `grade_num`）。題目難度 b＝g＋題型差：看英選中 0、看中選英 +0.4、拼字 +0.7（拼字保留首字母提示）。

**答對機率**（三參數邏輯模型）：

```
P(答對) = c + (1 − c) / (1 + e^(−1.1·(θ − b)))
```

c 是猜對率：選擇題 0.25（四選一），拼字 0。

**估計方式**：不用傳統的最大概似，而是在 θ 的格點（0.5～13，每 0.1）上算貝氏後驗平均（EAP），同時得到標準誤 se。好處是 8 題也不會發散，而且可以放入先驗：

| | 先驗平均 μ | 先驗標準差 σ |
|---|---|---|
| 搬家日 | 玩家自填的年級；沒填就 4 | 3（很寬，自填只影響第一題） |
| 每日小測 | 昨天的估計 θ | √(se² + 0.12 × 距上次天數)，限制在 0.6～2 |

每日小測的先驗等於一個簡化的卡曼濾波：昨天的估計是起點，隔越多天不確定性越大，所以估計值天天都穩定（不會因為一次手滑掉一個年級），但幾週下來會跟著真實進步移動。

**出題**：題型依序輪流「看英選中 → 看中選英 → 拼字」；θ 低於 2.2 時（小一小二程度）拼字題減少為每六題一題。第一題刻意比先驗簡單 1.2 個年級（讓人安心），之後每題挑難度最接近 θ+0.3 的字（對這個模型來說資訊量最大、又稍微偏向答得出來）。候選字排除：沒有年級的字、片語與縮寫、最近 80 次測驗出過的字、非名詞／動詞／形容詞／副詞／數詞／感嘆詞；拼字題只出可拼的字，θ<4 時限制 5 個字母以內，否則 8 個字母以內。選擇題的干擾選項取同詞性、年級相近（±2 或 ±1）的字，並沿用 0.92.45 的「任何一個意思都不能和答案重疊」檢查。

**停止**：搬家日最少 8 題，se<0.75 就停，最多 12 題；每日小測固定 8 題。

**模擬驗證**（`tests` 以外的本機腳本，用相同模型但稍微不同的鑑別度產生作答）：搬家日 60 次平均誤差約 0.55～0.9 個年級；每天小測、真實程度每天進步 0.1 的情況下，30 天內平均誤差約 0.45；自填年級差 4 個年級也能在搬家日被拉回。

## 3. 和遊戲其他系統的關係

| 系統 | 關係 |
|---|---|
| 自適應出題（`adaptive.js`） | 搬家日之後，把四種技能的能力值定錨到測出的年級對應的難度（`gradeToD` 分段對應：小一 0.3 … 國三 1.4 … 高一 1.8、高二 3.5、高三 5.5），所以第一天的每日複習就會拿到合適的字。之後年級移動滿 1 個年級才重新定錨，平常由自適應系統自己微調。測驗本身的作答**不會**改變技能能力值或 70～85% 的手感（它是量測，不是練習），也沒有幸運獎勵。 |
| Level 勾選 | 搬家日依年級設定：θ<9.5 只勾 L1；<10.5 勾 L1–2；<11.5 勾 L1–4；高三程度不限。之後玩家可自行改。 |
| 熟練盒（SRS） | 測驗題不影響單字的熟練盒。 |
| 每日任務 | `c_grade`，和其他任務一樣每天 06:00 重置。 |
| 社群名片 | `Social.card().grade` 多一個欄位；`profiles`／`board` 的 `firestore.rules` 已允許（12 字以內的字串）。 |
| 雲端存檔 | `Game.S.grade` 整包同步；合併存檔時以 `last` 較新的為準（`cloud.js mergeSaves`）。 |
| 學習紀錄 | 回合 `kind: 'grade'`、`sub: first|daily`，每題的 `p` 是本模型的預測，回合多一個 `pl` 摘要（欄位見設定教學第 10 節）。`learnlog` 規則已允許 `pl`。 |
| 開發者工具 | 重設單字進度時一併清除程度資料。 |

存檔欄位 `Game.S.grade`：`theta`、`se`、`n` 累計題數、`declared` 自填年級、`first`／`last` 日期、`hist[{d,t,se,n,r}]` 最近 120 次、`recent[]` 最近出過的字、`anchor` 上次定錨的年級、`asked` 搬家日被提示過幾次、`cert` 是否已送獎狀；`Game.S.settings.showGrade`（預設開）。

## 4. 後台「程度測驗」分頁

KPI：有程度資料的玩家、搬家日人數、每日小測回合、每人平均測驗次數、程度中位數、自填 vs 實測 ±1 內的比例、每日小測完成率（當天有來玩的人裡做了小測的比例）、7 天以上的平均成長。

圖表：玩家程度分布（最新一次 vs 自填）、自填 vs 實測表、每週平均程度趨勢、成長分布（第一次 vs 最近一次，相隔 7 天以上）、每日完成率、**題目難度是否標得準（item fit）**：以「題目難度 − 玩家程度」為橫軸，比較實際答對率和模型預測；三種題型分開畫。實線整體在虛線下方代表單字的年級標太低。

**單字年級修正建議**：只用測驗作答，對每個字比較實際答對率和模型預測，相差太多就換算成建議的年級調整 Δg（至少 12 次作答才列出）。「下載 CSV」得到 `grade-adjust.csv`，可以回填 `tools/vocab.json` 的 `grade_num`，再執行 `python tools/build-vocab.py` 和 `Update-Game.cmd`。建議累積 300 名學生兩週以上的資料再調，而且一次只調 |Δg| ≥ 1 的字。

## 6. 這一版沒有做的（和提案的差異）

- **聽音選圖**：依指示不做（圖片會佔容量）。
- **句子填空（cloze）**：單字表目前沒有例句資料，等有例句再加入成第四種題型；模型只要多一個題型差即可。
- **商人故事依年級分級**：故事仍依 Level 選字。可以在下一版用 `Game.S.grade.theta` 對應到 `gradeToD` 來選字。
- **「小窩英檢」挑戰模式**：每日小測已經是固定任務；是否另做每週一次、題數較多的挑戰，建議看 300 名學生的每日完成率再決定。
- **搬家日的箱子動畫**：目前用文字（「第 1 個箱子…」）呈現，沒有另外畫箱子的美術。

## 7. 給 300 名國小學生測試前的建議

1. 先推 0.92.46 和後台 v0.5，自己走一次搬家日與每日小測，確認名片標籤與獎狀。
2. 學生第一週的資料看「自填 vs 實測」和「每日小測完成率」；完成率低於 50% 表示任務入口不夠明顯或獎勵太少。
3. 兩週後看 item fit 圖和「單字年級修正建議」：國小字的年級是人工估的，這是第一次有真實資料可以校正。
4. 四週後看「成長分布」：若大多數人在 −0.5～+0.5 之間，代表量測穩定；正向偏移才是真正的學習效果，可以和每日複習的熟練盒進度對照。
