# 學習紀錄與分析：設定教學（新手版）

這份教學帶你從零開始，把「呼嚕小窩」的學習紀錄打開，然後用分析頁面看結果，最後用 AI 產生報告。

**需要多少時間**：第 1～5 步大約 30 分鐘。第 7 步（BigQuery）是進階選項，現在可以先跳過。

**需要準備**：

- 能登入 [Firebase 主控台](https://console.firebase.google.com/) 的 Google 帳號（就是建立 `pocket-nook` 專案的那個帳號）
- 遊戲專案資料夾 `D:\Dropbox\Github\html\game\Purr_Cozy`
- （第 6 步才需要）Anthropic 或 OpenAI 的 API 金鑰

## 0. 先了解整體運作方式

```
 玩家在遊戲裡答題、複習、拼字
          │  （js/learn-log.js 在背景記錄，先存在玩家瀏覽器）
          ▼
 每做完一個回合，整批上傳一次
          │  （用一個「只用來寫紀錄的匿名帳號」，不會影響玩家的登入和存檔）
          ▼
 Firebase Firestore：learnlog / {匿名ID} / lsess / {回合ID}
          │
          ├─► 後台 tools/admin.html（用 Google 登入，依角色讀取與管理）
          │        └─► 按一個按鈕，把「統計摘要」送給 Claude / ChatGPT 寫報告
          │
          └─► （進階）BigQuery：用 SQL 自己查
```

幾個重點：

- **只記錄學習相關的行為**：複習卡片、每一題的作答（題型、對錯、花了幾秒、選錯了哪個字）、貓咪打字的拼字過程。家具、寵物、聊天、名字和 Email 都**不會**記錄。
- **一個回合只寫一次資料庫**，費用很低（見第 8 步）。
- **離線也不會遺失**：沒網路時先存在玩家瀏覽器，下次連上網再補傳。
- **玩家可以關閉**：「設定」裡有「分享匿名學習紀錄」的開關。
- 規則設定成：玩家只能**新增**自己的紀錄，不能改、也不能看別人的；只有你（分析者）能讀取全部。

## 2. 在 Firebase 開啟「匿名登入」

遊戲用「匿名帳號」上傳紀錄，所以要先打開這個功能。

1. 打開 [Firebase 主控台](https://console.firebase.google.com/)，點選專案 **pocket-nook**。
2. 左邊選單點「**建構**」→「**Authentication**」。
3. 上方分頁點「**Sign-in method**」（登入方式）。
4. 在「登入供應商」列表找到「**匿名**」（Anonymous）。如果沒看到，就按「**新增供應商**」，再選「匿名」。
5. 把開關切到「**啟用**」，按「**儲存**」。

完成後，列表裡應該會看到「匿名：已啟用」，原本的 Google 和電子郵件登入也還在。

> 這個匿名帳號只用在學習紀錄，玩家完全看不到，也不會影響他們的「登入」和雲端存檔。

## 3. 後台帳號與權限，並發布安全規則

學習分析已經整合成後台：`tools/admin.html`（舊網址 `tools/learn-analytics.html` 會自動轉過去）。
左側是功能選單（儀表板、學習分析、AI 報告、資料與匯出、帳號與權限、操作紀錄、我的帳號），右側是內容與子分頁。

### 3-1. 三種角色

| 角色 | 在哪裡設定 | 可以做什麼 |
|---|---|---|
| 最高管理者 | Firebase 主控台的 `admins` 集合 | 全部功能；新增、停用、刪除管理者與分析者 |
| 管理者 | 後台「帳號與權限」 | 看全部分析、刪除玩家學習紀錄、管理分析者、查看操作紀錄 |
| 分析者 | 後台「帳號與權限」 | 看全部分析、下載資料、產生 AI 報告 |

任何人都不能修改自己的權限；管理者不能新增或修改其他管理者。這些限制寫在 `firestore.rules`，由 Firebase 伺服器把關，就算有人改了網頁程式也無法越權。

### 3-2. 設定最高管理者（只要做一次）

1. Firebase 主控台 →「Firestore Database」→「資料」分頁。
2. 按「**開始集合**」（或「新增集合」），集合 ID 填 `admins`。
3. 「文件 ID」填你的 Gmail，**全部小寫**，例如 `jamiace@gmail.com`（不要用自動產生的 ID）。
4. 加一個任意欄位，例如 `name`（字串，值可以留空），按「儲存」。
5. 要再加最高管理者，就在 `admins` 裡再新增一份文件；移除就刪掉那份文件。

> 舊版用過的 `analysts` 集合已經不再使用，可以刪除。原本在裡面、但不是最高管理者的人（例如同事），請改到後台「帳號與權限」新增。

### 3-3. 發布規則（用網頁，最簡單）

1. Firebase 主控台 → 左邊「**建構**」→「**Firestore Database**」。
2. 上方分頁點「**規則**」（Rules）。
3. 把編輯器裡的內容**全部選取並刪除**，再把 `firestore.rules` 的**整個檔案內容**複製貼上。
4. 按「**發布**」（Publish）。如果出現紅字錯誤，通常是貼的時候少了一部分，請重新完整貼一次。

> **重要**：一定要貼「整個檔案」，不能只貼新增的那段。規則是整份替換的，只貼一段的話，雲端存檔、好友、排行榜的規則都會不見。
>
> 會用指令列的話，也可以在專案資料夾執行 `npx firebase-tools deploy --only firestore:rules`，效果一樣。

### 3-4. 把改好的規則檔也 commit

`firestore.rules` 改了之後也要 commit、push，讓 GitHub 上的版本和 Firebase 一致。這個檔案不會被打包進遊戲，所以不用重跑 `Update-Game.cmd`。

---

### 3-5. 其他帳號：在後台新增（規則發布之後）

1. 用最高管理者帳號打開後台並登入。
2. 左側「**帳號與權限**」→ 下方「新增或編輯帳號」：填 Gmail、名稱、角色、備註，按「新增帳號」。
3. 對方用那個 Gmail 以 Google 登入後台就能使用。之後可以在列表「編輯」角色、「停用」或「刪除」。
4. 所有登入、讀取、下載、帳號異動都會記在「**操作紀錄**」，紀錄不能修改或刪除。

## 4. 確認紀錄真的有上傳

1. 打開遊戲（線上版），做一次「學習」→ 任何一種練習，把題目做完。
2. 等大約 10 秒。
3. Firebase 主控台 →「**Firestore Database**」→「**資料**」（Data）分頁。
4. 應該會看到一個新的集合 **`learnlog`**，點進去：
   `learnlog` → 一串匿名 ID → `lsess` → 一筆回合資料，裡面有 `ans`（作答）、`rev`（複習）等欄位。

看到了就代表成功了。

**沒看到的話**：

- 確認第 2 步的匿名登入有啟用。
- 確認遊戲已經是新版本：設定裡應該會出現「分享匿名學習紀錄」的開關，而且是「分享」。
- 在遊戲按 F12 → Console，看有沒有 `[learnlog]` 開頭的訊息：
  - `anonymous sign-in is not enabled`：第 2 步沒做好。
  - `upload later`：網路或規則的問題，會自動重試。
  - `dropped ... permission`：規則沒有發布成功，回到第 3-3 步。

## 5. 使用分析頁面

網址：`https://jamiace.github.io/html/game/Purr_Cozy/tools/admin.html`（舊網址 `learn-analytics.html` 會自動轉過來）。登入後依角色顯示左側選單；學習分析的各項圖表在「學習分析」頁的子分頁。

### 讀取資料（三種方式）

| 按鈕 | 什麼時候用 |
|---|---|
| **用 Google 登入並讀取紀錄** | 讀取最新的雲端資料。每個回合算 1 次 Firestore 讀取 |
| **開啟 JSON 檔** | 讀取之前下載的資料，不花讀取次數 |
| **用示範資料看看** | 還沒有真實資料時，先看每張圖表的樣子 |

**省錢的習慣**：每週登入讀一次，讀完按「**下載目前資料（JSON）**」存到電腦。平常要看就用「開啟 JSON 檔」。

### 篩選

可以選日期範圍、學習入口、程度、遊戲版本。「單字最少作答數」是指一個字至少被答過幾次才列入單字分析（預設 20），太少的話答對率不準。

### 每個區塊在看什麼

| 區塊 | 回答的問題 | 可以怎麼用 |
|---|---|---|
| 1. 總覽 | 多少人在學？答對率多少？ | 每週追蹤 |
| 2. 單字實測難度 | 每個字到底多難？哪些字的程度標錯了？ | 給編輯修正程度；按「下載 CSV」交給內容團隊 |
| 3. 程度 × 題型 | 拼字是不是比選擇題難太多？ | 調整題型比例 |
| 4. 易混淆字與拼錯 | 學生最常選錯成哪個字？最常怎麼拼錯？ | 做易混淆字專題；改善干擾選項 |
| 5. 遺忘曲線 | 隔幾天再出現還記得多少？ | 判斷複習間隔要拉長或縮短 |
| 6. 模型校正 | 遊戲預測的答對機率準不準？ | 工程師調整出題模型 |
| 7. 哪個入口學得最好 | 寵物訓練、每日複習、故事……哪個記得最牢？ | 決定要加強哪種玩法 |
| 8. 在哪裡放棄 | 卡在哪一題最多人離開？ | 縮短或簡化那一步 |
| 9. 留存與習慣 | 新玩家隔天、第 2 週、第 5 週還會回來嗎？幾點最多人學？ | 調整提醒時間、新手引導 |
| 10. 貓咪打字 | 拼字遊戲的難度，小貓搗蛋有沒有太干擾 | 調整打字遊戲 |
| 11. 提示與重聽 | 提示、重聽有沒有幫助？越後面的題目答對率是否下降？ | 調整每回合題數 |

> 資料量少的時候（例如前兩週），很多數字會跳動很大，先不要急著下結論。單字分析通常要每個字有 20 次以上的作答才比較可信。

## 6. 產生 AI 報告

分析頁面最下面的「**12. AI 分析報告**」，會把上面算好的**統計摘要**（只有數字和單字，沒有任何玩家 ID）送給 AI，請它寫成一份報告。

### 6-1. 申請 API 金鑰（二選一）

**Claude（Anthropic）**

1. 到 [Claude Console](https://platform.claude.com/) 註冊並登入。
2. 到「Billing」儲值（例如 5 美元，可以用很久）。
3. 到「API Keys」→「Create Key」，複製 `sk-ant-` 開頭的金鑰。

**ChatGPT（OpenAI）**

1. 到 [OpenAI Platform](https://platform.openai.com/) 登入。
2. 到「Billing」儲值。
3. 到「API keys」→「Create new secret key」，複製 `sk-` 開頭的金鑰。

> 建議在 Billing 頁面設定「每月用量上限」，避免金鑰外流時被盜用。

### 6-2. 產生報告

1. 先載入資料（第 5 步），確認上面的圖表都出來了。
2. 「服務」選 Claude 或 ChatGPT。
3. 「模型」保留預設就可以：Claude 是 `claude-opus-5-5`，OpenAI 是 `gpt-6.1-sol`。之後如果出了新模型，直接把名稱改成新的（可以到 [Claude 模型列表](https://platform.claude.com/docs/en/models/overview) 或 [OpenAI 模型列表](https://developers.openai.com/api/docs/models) 查）。
4. 貼上 API 金鑰。勾「記住金鑰」的話，它只會存在**這台電腦的這個瀏覽器**。在公用電腦上不要勾。
5. 「報告重點」選讀者是誰：完整報告、給編輯、給產品、給工程。
6. 「補充說明」可以寫這段期間做了什麼改變，例如「11/10 起每日任務從 20 字改成 15 字」，AI 就會把它納入分析。
7. 按「**產生 AI 報告**」，等 30～90 秒。
8. 按「**下載報告（.md）**」存起來，可以直接貼到 Notion、HackMD，或轉成文件分享。

想知道到底送了什麼給 AI，可以按「**先看要送出的摘要**」。

### 6-3. 費用

一次報告大約送出 1 萬個 token、收回 3 千個 token。依模型不同，大約是 **0.05～0.5 美元一次**。

## 7. （進階，可跳過）接上 BigQuery

**什麼時候需要**：紀錄超過大約 5 萬個回合，分析頁面開始變慢，或者你想用 SQL 自己做更深入的分析（例如重新訓練出題模型）。在那之前，分析頁面就夠用了。

**前置條件**：Firebase 專案必須升級成 **Blaze（用量計費）方案**。小量使用通常還是在免費額度內，但一定要綁信用卡。

### 7-1. 升級方案並設定預算提醒

1. Firebase 主控台左下角「Spark」旁邊按「**升級**」，選 **Blaze**，綁定帳單帳戶。
2. 到 [Google Cloud 帳單 → 預算與快訊](https://console.cloud.google.com/billing/budgets)，建立一個預算（例如每月 10 美元），在 50%、90%、100% 時寄信提醒你。

### 7-2. 安裝「Stream Firestore to BigQuery」擴充功能

1. Firebase 主控台 → 左邊「**擴充功能**」（Extensions）→ 搜尋 **Stream Firestore to BigQuery** → 「安裝」。
2. 設定時，重要的欄位這樣填：
   - **Collection path**：`learnlog/{logId}/lsess`
   - **Dataset ID**：`purr_learning`
   - **Table ID**：`sessions`
   - **BigQuery dataset location**：`asia-east1`（台灣）
   - 其他保持預設。
3. 安裝需要幾分鐘。之後**新的**紀錄會自動同步到 BigQuery。

### 7-3. 把已經存在的舊紀錄也匯入（只需要做一次）

擴充功能只會同步「安裝之後」新增的資料。舊資料要用官方工具匯入，需要先安裝 [Node.js](https://nodejs.org/)（選 LTS 版）。

1. 安裝 Google Cloud CLI，然後執行 `gcloud auth application-default login`，用你的 Google 帳號登入。
2. 執行 `npx @firebaseextensions/fs-bq-import-collection`，依序回答：
   - Project ID：`pocket-nook`
   - Source collection path：`lsess`
   - Collection group query：`y`（是）
   - Dataset ID：`purr_learning`、Table prefix：`sessions`
   - 其他按 Enter 用預設值

### 7-4. 在 BigQuery 查詢

打開 [BigQuery 主控台](https://console.cloud.google.com/bigquery)，左邊會看到 `purr_learning` → `sessions_raw_latest`（每個回合的最新內容）。資料存在 `data` 欄位裡，是 JSON 文字。

**範例 1：每個單字的答對率（作答 20 次以上）**

```sql
SELECT
  JSON_VALUE(a, '$.w') AS word,
  CAST(JSON_VALUE(a, '$.l') AS INT64) AS level,
  COUNT(*) AS n,
  ROUND(AVG(CAST(JSON_VALUE(a, '$.ok') AS INT64)), 3) AS accuracy,
  APPROX_QUANTILES(CAST(JSON_VALUE(a, '$.ms') AS INT64), 2)[OFFSET(1)] / 1000 AS median_sec
FROM `pocket-nook.purr_learning.sessions_raw_latest`,
  UNNEST(JSON_QUERY_ARRAY(data, '$.ans')) AS a
GROUP BY word, level
HAVING n >= 20
ORDER BY accuracy
```

**範例 2：每天的學習人數與作答題數**

```sql
SELECT
  DATE(TIMESTAMP_MILLIS(CAST(JSON_VALUE(data, '$.t0') AS INT64)), 'Asia/Taipei') AS day,
  COUNT(DISTINCT JSON_VALUE(data, '$.lid')) AS learners,
  SUM(ARRAY_LENGTH(JSON_QUERY_ARRAY(data, '$.ans'))) AS answers
FROM `pocket-nook.purr_learning.sessions_raw_latest`
GROUP BY day
ORDER BY day
```

**範例 3：最常見的混淆字**

```sql
SELECT JSON_VALUE(a, '$.w') AS answer, JSON_VALUE(a, '$.g') AS chosen, COUNT(*) AS n
FROM `pocket-nook.purr_learning.sessions_raw_latest`,
  UNNEST(JSON_QUERY_ARRAY(data, '$.ans')) AS a
WHERE JSON_VALUE(a, '$.ok') = '0' AND JSON_VALUE(a, '$.q') IN ('en2zh', 'zh2en', 'listen')
GROUP BY answer, chosen
ORDER BY n DESC
LIMIT 50
```

查詢結果可以按「**探索資料**」→「Looker Studio」，做成可以分享的圖表報表。

## 8. 費用估算

Firestore 免費額度（Spark 和 Blaze 方案都有）：**每天 2 萬次寫入、5 萬次讀取、1 GB 儲存空間**。

| 項目 | 計算方式 | 例子 |
|---|---|---|
| 寫入 | 一個學習回合 = 1 次 | 500 位玩家 × 每天 3 回合 = 每天 1,500 次（免費額度的 7.5%） |
| 讀取 | 分析頁面每讀 1 個回合 = 1 次 | 一次讀 3 萬個回合 = 3 萬次（當天免費額度的 60%） |
| 儲存 | 每個回合約 2～4 KB | 10 萬個回合約 300 MB |
| 匿名登入 | 免費 | |

**建議**：分析頁面讀完就下載 JSON，不要一天之內重複登入讀取好幾次。

## 9. 隱私與玩家告知

學習紀錄不含名字和 Email，但仍然算是「和某個人相關的使用資料」。玩家很可能是高中生（未成年），請注意：

1. **在遊戲的隱私說明或網站上加一段告知**，例如：

   > 為了改善單字難度和題目，呼嚕小窩會記錄你在遊戲中的學習情形（例如單字、題型、對錯、作答時間）。這些紀錄使用匿名編號，不包含你的名字、Email 或房間內容，只用於統計分析。你可以隨時在「設定 → 分享匿名學習紀錄」關閉。

2. **玩家關閉開關後**：遊戲會停止記錄，並清除還沒上傳的紀錄。
3. **玩家要求刪除資料時**：
   - 如果他有登入，紀錄裡的 `acct` 欄位就是他的帳號 UID。在 Firestore「資料」分頁篩選 `acct` 等於他的 UID，就能找到並刪除。
   - 如果沒有登入，資料無法對應到個人，本來就是匿名的。
4. **保存期限**：建議只保留 2 年，定期把太舊的資料刪掉。想要自動刪除的話，可以請 Claude 在紀錄裡加一個「到期時間」欄位，再用 Firestore 的 TTL（存留時間）政策自動清除。注意不能直接對 `at` 欄位設定 TTL，`at` 是上傳時間，資料一上傳就會被刪掉。
5. **要給學校或班級使用時**：依學校規定，可能需要取得家長同意。
6. **AI 報告**：只會送出統計摘要（數字和單字），不會送出任何玩家編號。

## 10. 資料欄位說明

每一份 `learnlog/{logId}/lsess/{sessionId}` 文件是一個學習回合：

| 欄位 | 意思 |
|---|---|
| `lid` | 匿名紀錄 ID（只用在學習紀錄） |
| `acct` | 玩家有登入時，他的帳號 UID；沒登入時是空的 |
| `dev` | 裝置代號（同一台瀏覽器相同） |
| `app` / `lang` | 遊戲版本、介面語言 |
| `kind` | 學習入口：`daily` 每日複習、`practice` 自由練習、`need` 房間泡泡、`train` 寵物訓練、`help` 幫朋友、`story` 故事、`team` 團隊、`chal` 挑戰、`levelgate` 升級考、`typo` 貓咪打字 |
| `sub` | 入口細項（挑戰代號、故事章節、寵物招式等） |
| `t0` / `t1` / `dur` | 開始時間、結束時間（毫秒時間戳記）、經過毫秒數 |
| `done` | 有沒有做到結果頁 |
| `stop` | 停在哪裡：`result` 完成、`quiz@3/8` 測驗第 4 題離開、`review@5/20` 複習第 6 張離開、`restart` 改做別的、`left` 關閉、`idle` 閒置超過 30 分鐘 |
| `n` / `right` | 題數、答對數 |
| `coins` / `xp` / `streak` | 這回合拿到的金幣、經驗值、當時的連續天數 |
| `lv` | 玩家勾選的程度，例如 `123` 代表 L1～L3 |
| `at` | 伺服器收到的時間 |

**`ans`：每一題作答**

| 欄位 | 意思 |
|---|---|
| `w` / `l` | 單字、程度（1～6） |
| `q` | 題型：`en2zh` 看英選中、`zh2en` 看中選英、`listen` 聽音選義、`spell` 拼字、`listenspell` 聽寫 |
| `ok` | 1 答對、0 答錯 |
| `ms` | 作答時間（毫秒，從題目出現到作答） |
| `g` | 答錯時的答案：選擇題是被選的那個字，拼字題是玩家打的字 |
| `b0` / `b1` | 作答前、作答後的熟練盒（0～5） |
| `gap` | 距離上次作答這個字幾天（-1 = 第一次） |
| `p` | 出題時模型預測的答對機率（-1 = 沒有） |
| `h` | 拼字題有沒有提示（1 有） |
| `r` | 重聽發音的次數 |
| `i` | 這回合的第幾題（從 0 開始） |
| `re` | 1 = 回合最後重做答錯的題目 |
| `t` | 從回合開始到作答的毫秒數 |

**`rev`：每日複習的卡片**：`w` 單字、`l` 程度、`k` 1 = 按「認得」、0 = 按「不熟」、`ms` 看卡片的時間。

**`typo`：貓咪打字的每個字**：`w` 單字、`l` 程度、`ok` 最後拼對、`att` 送出次數、`ms` 時間、`rv` 1 = 直接看答案、`cat` 1 = 被小貓搗蛋過、`g` 拼錯時打的字（最多 3 個）。

## 11. 常見問題

**Q：後台顯示「沒有後台權限」**

A：最高管理者：確認 Firebase 的 `admins` 集合有一份文件，文件 ID 和登入畫面顯示的 Gmail 完全一樣（全部小寫），而且 `firestore.rules` 已發布最新版。其他人：請最高管理者或管理者在「帳號與權限」新增，並確認帳號是「啟用」。

**Q：後台顯示「讀不到 firebase-config.js」**

A：這個頁面要從網站上開（`https://jamiace.github.io/.../tools/admin.html`），不能直接雙擊電腦裡的檔案。如果是在電腦上直接開，只能用「開啟 JSON 檔」和「示範資料」。

**Q：Google 登入視窗跳出來又關掉**

A：瀏覽器擋了彈出視窗，請允許 `jamiace.github.io` 開啟彈出視窗。

**Q：玩家說他關掉分享了，還會被記錄嗎？**

A：不會。關掉的當下，還沒上傳的紀錄會一起清除，之後也不會再記錄。

**Q：同一個玩家在手機和電腦都玩，會被算成兩個人嗎？**

A：沒登入的話會（`lid` 不同）。有登入的話，兩邊的 `acct` 相同。目前分析頁面用 `lid` 計算人數，所以「學習人數」會稍微高估。

**Q：AI 報告說的東西可以全信嗎？**

A：不行。AI 是根據統計摘要寫的，可能會過度解讀樣本很小的數字。請把它當作「幫你整理重點和提出假設的助手」，重要的決定要回到圖表確認，最好再用 A/B 測試驗證。

**Q：我想改記錄的內容**

A：記錄的程式在 `js/learn-log.js`。如果新增欄位，`firestore.rules` 裡 `validLearnLog` 的欄位清單也要一起加，不然上傳會被拒絕。
