# Purr Cozy 0.92.19
覆蓋 0.92.18，保留音樂檔與其他原有檔案。先上傳改動檔案與 resources.json，最後上傳 version.json。

## 啟動卡在 98% 的修正
線上抽查證實：PNG 正確，但 index.html、asset-cache.js、hd-furniture.js、sw.js 的 GitHub 版本為 LF，本機清單卻以 CRLF 位元組校驗，造成拒絕載入。工具及載入器現統一文字換行為 LF 再做 CRC32／大小檢查。圖片等二進位內容不正規化。
第一個錯誤會保留檔名，不再被其他下載工作覆蓋；單一請求逾時改為 25 秒。部分下載完成的檔案仍可供下次沿用。這不代表所有網路錯誤都能自動修復；重新載入仍失敗時可看到真正錯誤。

## 音樂與播放清單
音樂音檔（mp3、flac、m4a、wav、ogg、aac、oga、opus、webm）不計算 checksum、不加入啟動預載；原本的音樂串流／按需快取維持。歌詞、封面與內建清單仍是可更新資料。
內建專輯清單獨立為 data/music-builtins.json，本次由現有 playlist.json 轉入 26 首歌曲。舊 music/playlist.json 不再讀取；未來修改 data/music-builtins.json 後跑 Update-Game.cmd。內建 YouTube 電台仍使用 music_default.js 與 music_yt_tracks.js，皆為隨程式更新的內建資料。
玩家自建 YouTube／本機歌曲清單留在帳號存檔 music.list，不加入資源 checksum，不會被內建清單更新取代。舊混合清單自動分開：只有內建電台的執行期複本，序列化到本機與雲端時只保存自建項目、播放偏好與最後選擇。原有雲端登入與存檔流程沿用，清單異動也計入同步衝突判斷。
本機匯入音檔的「清單資料」會同步，音檔本身依舊只在匯入的裝置 IndexedDB；沒有新增雲端音檔上傳功能。換裝置時 YouTube 項目可直接使用，本機歌曲仍需重新提供音檔。
介面區分「內建音樂」與「我的清單」，個人清單不顯示內建電台、不允許把個人項目移到內建項目前或刪除內建項目。
