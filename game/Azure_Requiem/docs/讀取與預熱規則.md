# 讀取畫面與預熱規則（2026-11-28 使用者指定，44.38 起）

## 原則
- 讀取畫面的意思：**在這個過程中，把選定關卡會用到的所有東西載入，並把這一關裡所有「會呈現出來」的東西都預熱**——不管它現在有沒有觸發，只要這一關會出現，就要在讀取時準備好。
- 遊戲開始之後，不應該有任何東西是「第一次出現才建立、才編譯」。
- 不能用「清單上有的才預熱」的做法，也不能等使用者或偵測器發現卡頓才補。新增任何會畫在畫面上的東西時，同時決定它在讀取時怎麼先建好。

## 做法（44.38）
- 出擊：先蓋上讀取畫面、停掉編成音樂（0.4 秒淡出），畫面真的畫出來後才開始準備。
- 讀取時建立：這一關所有機種＋塗裝（含之後才出場的波次、第二關的無人機與 RAVEN 1、特殊兵裝放出的友軍無人機）、飛彈模型與尾焰、每架飛機的音速錐、會電漿匿蹤的飛機的電漿殼、ANZU 碎片。
- 黑畫面的兩格：把場景裡所有東西（含隱藏的特效池、特殊兵裝、ANZU 部件、核爆）全部打開、關掉視錐剔除，用實際的繪製管線（體積雲、特效圖層、倒影）畫一次。
- 驗收：遲到編譯偵測器（main.ts lateCompileCheck）。讀取結束後只要有著色器第一次編譯，就記在 window.__lateCompiles 並在主控台印 [late-compile]。兩關跑完、所有事件都觸發過，偵測器必須是零才算完成。

## 語音（44.43 使用者指定：「解」）
- 讀取畫面裡把這一關所有劇情語音解碼完才結束讀取：第一關 SCN-／M1-（114 段，約多 45 MB），第二關 M2-（379 段，約多 200 MB）。
- 整場任務都留著，不再講完就釋放；換到另一關時，上一關留著的才釋放。取代 44.05 版「排進無線電才解碼、講完就釋放」。
- 戰鬥中反覆使用的台詞與警告系統照舊在開網頁時就解碼常駐。

## 卡頓記錄（44.43）
- core/StallWatch.ts：遊戲中兩格之間超過 50 ms 就記在 window.__stalls（主控台 [stall]），附上那兩格發生的事（配樂、台詞、解碼、HUD 新框、選定目標、事件、遲到編譯、顯示卡資源與記憶體變化）。
