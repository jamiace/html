## 0. 一句話定位與設計原則

**定位**：受《ACE COMBAT》系列（主要參考 AC7／AC8）啟發的瀏覽器 3D 空戰狗鬥遊戲。一個完整關卡「DEMO MISSION D01 FIRST CONTACT」：玩家 Joker 1 帶三架僚機，打三波敵機，最後是王牌 Tyrant 與他的 Cerberus 小隊。

**核心設計原則**（貫穿所有系統）：

1. **手感依實測校準，不憑感覺**：轉彎率、滾轉、High-G 倍率、進入延遲、高度失速都對照 AC7 玩家實測與 AC8 資料檔換算（見 §4、`docs/FLIGHT_TELEMETRY.md`）。
2. **AI 不作弊**：AI 和玩家用同一套飛行物理、只能輸出相同的操縱輸入；「閃躲能力」換算成飛行技巧，不是數值護盾。
3. **同一份資料是唯一真相**：地形高度（碰撞、AI、陰影、畫面、雷達、重播共用）、兵裝資料表、機體資料表全部資料驅動；參數面板（F2）即時修改同一份物件。
4. **玩家要「看得到」的才算數**：所有改動都要在使用者的機器上截圖驗證；看不出差別的加強等於沒做。
5. **專業素材優先**：爆炸、火焰、煙等用現成的專業逐格動畫（Unity Labs CC0），雲用 Takram three-clouds，海用 Three.js 官方 Water；不手刻能找到更好替代品的東西。
6. **不交有問題的東西**：每次交付都經過型別檢查、自動測試、實機截圖；做不到或沒驗證的事明講。
7. **溝通一律用繁體中文**（使用者要求）。

## 2. 建置、部署、檔案格式

### 2.1 指令

```bash
npm run build          # 單一檔案 dist/index.html（約 36 MB，所有東西內嵌）
node build.mjs --split # 拆檔版 dist/split/（第 41.28 版起的正式交付方式）
npm run dev            # http://localhost:8000，每次重新整理都重建
npm run typecheck
npm test               # 無畫面模擬：飛行物理＋完整 AI 對戰（8 場預設＋變化）
npm run test:story     # 劇情導演測試（台詞、配樂順序、階段）
```

### 2.2 拆檔版（目前的正式版）

使用者要求「index.html 不要那麼大一包」：

```
Azure_Requiem/
├─ index.html          約 3 MB：程式碼＋內建音效（base64）
├─ assets/             貼圖（webp/jpg/png）、雲形狀與地形資料（.bin），檔名帶雜湊（更新不吃舊快取）
├─ models/*.glb        機體、飛彈、艦艇、防空砲、SAM 發射車（不再內嵌）
├─ music/*.mp3         配樂
├─ voice/voice_pack.bin  全部語音打包成一檔
├─ sound/sound_pack.bin  全部音效＋manifest.json 打包成一檔
└─ head/*.png          無線電頭像
```

- 貼圖用 esbuild `file` loader，`publicPath: '.'`。
- `.bin`（雲形狀、地形）是程式一啟動就要「同步」用到的，用同步 XHR 讀成 `Uint8Array`（`overrideMimeType('text/plain; charset=x-user-defined')`，逐字元 `& 255`）。
- 模型在拆檔版裡被 esbuild 外掛換成 `module.exports = null`，執行時只從 `models/` 讀（`GltfModels.preloadModels`）。
- **必須用網頁伺服器開啟**（使用者有 `local_server.bat`；或 GitHub Pages），`file://` 讀不到外部檔。
- 使用者說「先拆開，確認 final 再打包」：將來可能再合併成單檔。

### 2.3 打包檔格式（語音包、音效包共用）

```
'ARVOICE1'（8 bytes）
索引長度 n（uint32 little-endian）
索引 JSON（n bytes）：{ "files": [[檔名, 起點, 長度], ...] }
資料（所有檔案串接）
```

- 產生：`python tools/make-pack.py <資料夾> <輸出檔>`（音效：`sound` → `sound/sound_pack.bin`，含 `manifest.json`）。語音包由「語音工作室」的打包功能產生。
- 讀取：`Audio.ts` 的 `loadPack()`、`Radio.ts` 的 `loadVoicePack()`；`fetch(..., { cache: 'no-cache' })`，GitHub Pages 預設快取 10 分鐘，不這樣做重新上傳的包要等快取過期。
- 為什麼打包：GitHub Pages 一次要求幾百個小檔會回 429；而且使用者明說「voice 跟 sound 要打包，因為檔案太多了」。
- Git LFS 的指標檔會被偵測出來並在設定頁說明（Pages 不支援 LFS）。

### 2.4 音效對照表

`sound/manifest.json`：「音效欄位 → 檔名」，每項可以是字串或 `{ file, volume }`。優先順序：內建音效 → `sound/`（或 sound_pack） → 使用者在瀏覽器裡手動匯入（IndexedDB）。

### 2.5 網址參數

`?test=1`（第一波立即進場、結算不等待）、`?sea=legacy|water`、`?clouds=classic`、`?allAircraft=1`。

### 2.6 使用者環境（目前）

- 遊戲資料夾：`D:\Dropbox\Github\html\game\Azure_Requiem`，用 `local_server.bat` 開在 `localhost:8000`。
- 顯示卡：RTX 3070 Laptop；螢幕 144 Hz；瀏覽器 DPR 1.5。
- 測試版放 `_dev/index.html`（`<base href="../">`，資源讀根目錄）。

## 3. 座標、單位與共用慣例

- **世界座標**：Y 向上；機鼻朝 −Z（`FORWARD = (0,0,-1)`），右方 +X。航向 yaw 0 = 北（−Z）。
- **模擬單位**：公尺、秒、弧度；**顯示單位**：速度一律節（kt，×1.94384）、高度一律英尺（ft，×3.28084）、距離只顯示英尺數字。
- 參數面板裡的欄位可指定 `scale`（例如顯示成 kt／ft，寫回時換算）。
- 戰場：`ARENA_HALF` 定義的方形；超出有 OUT OF AREA 無線電；`ARENA_HARD` 為硬邊界。
- 世界放在經度 **東經 25°**（Takram 的地球是圓的；放在方塊面中央附近會有浮點精度問題，雲被切出南北向直線）。
- **地球曲率**（第 41.27 版）：體積雲模式下，所有物件的「畫面位置」依離鏡頭的水平距離往下彎（10 km 約 8 m、50 km 約 196 m、180 km 約 2.5 km），模擬不受影響；`EARTH_CURVE` define＋`curveMV()`。原因：體積雲與大氣在圓的地球上，平的海面會讓海平線高於真正的地平線，遠處的雲被切成一條直線。海面加大到 900 km 見方、跟著鏡頭移動。正交攝影機（陰影圖）不彎。
- **權威高度**：`terrainHeight(x,z)` = 畫面上的地表高度；碰撞、影子、AI 避地、視線遮蔽、地面單位、樹全部用它（第 41.10f 版統一；之前碰撞用原始海拔，比畫面低 14 m，飛彈鑽進地下才爆）。

## 4. 飛行模型

`flight/FlightPhysics.ts`。玩家與所有 AI 共用。

### 4.1 機鼻與速度向量分離
- 速度向量以有上限的速率追向機鼻，機鼻可以先轉過去。一般全拉桿攻角約 8°，High-G 約 18～20°。
- 攻角限制器：接近上限時自動減少拉桿量（`alphaSoft`／`alphaHard`，High-G 另一組）。
- 機砲沿機鼻射擊 → High-G 時可以先把機鼻甩到目標前方開火。

### 4.2 轉向校準（AC7 實測）
- 條件：約 1,900 m、550 kt 水平飛行、滾轉 90° 後全拉桿，取 0.6～1.4 秒平均航跡轉向率換算成「等效轉一圈秒數」。各機型誤差 0.02 秒內。
- 拉桿時角速度建立、放桿時消退的快慢分開（AC8 資料檔 AddRotR／DecRotR 換算）。
- 放桿慣性：滾轉多轉約 17～24°、俯仰 8～11°；反向打立刻停。

### 4.3 High-G 狀態機
進入延遲（依機型 0.17～0.34 s）→ 全力 2.2 s → 繼續按住時效果 60% → 放開 0.35 s 內退回；放開再按可重新觸發。倍率 1.33～1.41。凝結雲與風切聲只看「有沒有按住」，與實際增益分開。

### 4.4 耗能
基本阻力、轉彎阻力（速度 × 轉向率²）、攻角阻力、High-G 額外減速、空氣煞車、重力分量逐項計算。550 kt 全拉桿 3 s：一般剩約 520～550 kt，High-G 約 405～450 kt。

### 4.5 俯衝越衝越快
機鼻朝下時重力加速倍率隨時間增加（依 SpeedDownerR，最多 3.5 倍），抬頭後很快退回。超過極速後阻力急增。

### 4.6 PSM（失速後機動，AC8 資料檔分類）
- Kulbit（F-22、Su-35、Su-57）：按住整圈翻轉，放開停在當下角度。
- Cobra（F-35、Su-30、Su-47）：仰起約 105～110° 後自動回正。
- F/A-18、F-14：沒有 PSM。
- 觸發：L2+R2 剛按下的 0.35 s 內滿拉桿、速度低於機型上限（HUD 出現 PSM READY）。PSM 期間速度向量幾乎維持原方向。

### 4.7 三層失速
低速抖振（鏡頭輕震）→ 低於最低可控速度：STALL、舵效下降 → 低於其 78%：失控、機鼻下墜。失速保留操縱：俯仰 5%、滾轉 10%、偏航 40%。

### 4.8 高度限制（依 AC7／AC8 研究，`docs/ACE_COMBAT_ALTITUDE_STALL_RESEARCH.md`）
- 約 24,000 ft 起推力逐漸下降、爬升額外付速度。
- 各機型強制失速高度 30,000～33,000 ft（`ceilingFt`），下方 1,000 m 是失速帶。
- **33,500 ft 隱形天花板**：碰到時垂直速度歸零、速度保留。
- PSM 可越過強制失速高度直到天花板，結束後失速（同 AC7）。
- 失速時機鼻下拉強度依機型，以世界座標朝地方向拉。

### 4.9 低空與碰撞
- 機體中心離地 2 m 內才算撞上，可以貼海 30 ft 飛行。
- 撞地依難度扣血（簡單 15%／普通 30%／困難 55%／ACE 直接墜毀），彈回空中、1.5 s 內不重複扣。
- 同陣營互相穿透。

### 4.10 F-14 可變後掠翼與舵面
- 依速度 520～1,250 km/h 逐漸後掠；減速超過 0.3（第 41.17 版加遲滯）或 High-G 時展開，動作放慢。
- 水平尾翼、方向舵、副翼、鴨翼／LEVCON 依輸入偏轉；F-14 用差動尾翼滾轉，Su-57 垂尾整片轉。

- 自適應扳機：L2／R2 在 70% 行程有阻力牆；High-G 要兩個都壓過 80%；後燃器門檻 92%。選單、暫停、結算時扳機回原位。

## 7. 鏡頭

- 機後鏡頭朝向取機鼻與速度向量之間（一般權重 0.5、High-G 0.8），攻角看得見；方向與滾轉各自追隨（0.14／0.2 s），機動時機體在畫面裡移動。
- AC7 比例（第 41.14 版）：機體約占畫面寬六成（距離 1/2.1、俯視 3°）。
- High-G 時機身模型在畫面上仰起最多 15°（純視覺）。
- PSM 期間鏡頭以速度向量為主、拉遠拉高，上方向固定，畫面不跟著翻。
- 後燃器點燃時鏡頭被甩開再跟上、視野漸寬（抖動已減半）。
- 暫停、凍結時不抖動。
- 速度線：消失點 = 實際前進方向的畫面位置；推力 > 75% 才出現；濃度乘速度係數。空拍機不套用。

### 8.4 飛彈命中部位

- **EML**：三連發；前置點在機鼻 2° 內直接射向前置點、2～4° 往前置點修正 2°、更遠照機鼻直射。發射音是程式即時合成（爆裂＋下墜低頻＋電弧＋殘響，再疊兩層壓低音調的實錄爆炸）。彈體藍金色光條，沿途離子尾跡與衝擊波環。

## 9. AI

`ai/AIController.ts`（約 1,160 行），一個類別處理三種角色：敵機、僚機、自動飛行（`demo = true`）。

### 9.1 鐵則
- 只能輸出和玩家相同的操縱輸入（拉桿、滾轉、偏航、油門、High-G、PSM），不改位置速度。
- 跟不上 F-22 極限急轉時就被甩開，再追回來。

### 9.2 風格、技術、難度（`data/aiProfiles.ts`）
- 敵機風格：均衡、編隊協同、攻擊型、高機動型、擾亂型、高速脫離型、獵殺型（積極度、High-G 傾向、攻擊後是否脫離、耐心、能量偏好、重選目標間隔、是否跟隨長機、是否用 PSM）。
- 技術等級 1～4（新手／一般／老手／菁英）：反應間隔 0.75→0.22 s、瞄準誤差、鎖定到發射延遲、發射間隔、機砲門檻、熱焰彈技巧、閃躲品質、速度管理、拉桿上限、High-G 意願。
- Tyrant 專屬技術（不受難度影響）。
- 難度：簡單／普通／困難／ACE —— 敵機基礎技術、玩家可承受幾發飛彈（8／5／3／1.5）、撞地與相撞傷害、機砲無限、敵砲倍率、同時追玩家的飛彈上限、敵機選玩家的偏好、追玩家飛彈的轉向倍率、鎖定玩家時間倍率、發射間隔倍率。
- AI 群組倍率（參數面板可調）：僚機（積極 0.5、命中 0.5、閃躲 20、耐久 5）、一般敵機（命中 0.3、耐久 0.85＝兩發標準飛彈）、敵方王牌（閃躲 3、耐久 1.75＝四發）、Tyrant 兩階段、僚機對 Tyrant 命中 0.05。

### 9.3 閃躲 = 飛行技巧
閃躲倍率換算成「看不看得出該用哪一招、時機準不準」：
- 飛彈還追不上：轉身全速逃離，讓它燒完推進、掉速自毀（先算追不追得上）。
- 追得上：把飛彈放到側面逼它耗速，最後往飛彈那側急轉。
- 在誘騙機會最大的距離（約 1,100 m）放熱焰彈。
結果：遠距離打不中高手，貼近就打得中。

### 9.4 僚機
- **指尖隊形**：左右 55 m、後方 35 m，四號機右後 110 m／70 m。
- 400 m 內用「加速度指令」：位置誤差 → 想要的速度 → 想要的加速度 → 拉桿（升力方向）、方向舵（側向）、油門（前後）；拉桿量考慮機鼻與速度向量落差。坡度跟隊長（含滾轉速度），最多差約 63°。油門用推力阻力估算＋積分。實測：位置誤差中位數 1 m、坡度差中位數 0°。
- 接觸前一律編隊。
- 命令：集中攻擊（打玩家選定的目標）、掩護（優先打攻擊玩家的敵機；有飛彈追玩家時切到中間放熱焰彈）、分散交戰、特殊兵裝開關。
- 自動飛行也會對僚機下命令（第 41.22 版）：每 2 s 評估、至少維持 15 s；被咬住 → 掩護；選定的王牌頭目在 6 km 內 → 集中攻擊；其他 → 自由。

### 9.5 自動飛行（展示 AI／玩家 AI）
暫停選單「自動飛行」開啟。演進了很多版，目前行為：

**選目標（`demoPick`）**
- 用 `sim.targetsOf(ac)`（玩家能鎖定的都算，含地面、海上）。
- **只要地圖上還有敵機（不論多遠），地面／海上目標一律排到最後（+1000 分）**（第 41.31 版，使用者要求「優先飛往敵機位置，而不是傻傻地去打地面白色目標」）。沒有敵機時才打地面（SAM 威脅較大先打）。
- 空中目標：距離 + 角度、救援被咬的僚機（僚機傷越重越優先）、咬我的、Tyrant 減傷中 +40（先清隊員）。
- 換目標要明顯更好（差 2.5 分）才換；正在 2.2 km 內、機鼻 0.35 rad 內打得到的不換。

**空戰飛法（`demoEngage`）**
- 遠距：碰撞航線攔截，相遇點用平滑過的目標速度、前置量最多 12°（避免十幾公里外目標一轉就甩機鼻）。
- 3.5 km 內：前置追擊；太近、接近太快改落後追擊並減速。
- 機鼻 20° 內、1.3 km 內：機砲前置點精確瞄準（加角速度阻尼、協調轉彎）。
- 飛彈只在後半球 3 km 內或 1.4 km 內發射；一鎖定就打、兩發都可能中時補第二發、冷卻中換別的兵裝。
- 操縱連續：角速度正比於誤差；偏差小直接俯仰偏航對準；偏差大滾到升力面再拉；輸入平滑約 0.06 s。
- 油門：想要的速度先平滑，每秒最多變 0.7；後燃器遲滯（0.97 點燃、0.8 以下收、點燃後至少 1.5 s）。
- High-G 遲滯（0.7 rad 開、0.45 關，至少 1.2 s、關掉 1 s 內不再開）；減速板遲滯固定 0.6。
- 飛法至少維持 1.2～2.2 s 不來回切。
- 僵局（3 s 判斷）：有 PSM 的機體近距離繞圈 1.5 s 後用 PSM 甩機鼻；否則先高 Yo-Yo，20 s 內再陷入才拉開（最多 5.5 s 或 2.6 km）。
- 只有對方 1 km 內機鼻正對我才急轉 2.5 s；飛彈剩 4 s 才處理；3 s 內會撞上才閃。側閃方向決定後固定。
- 沒有目標時平穩巡航（坡度 ≤ 43°、交戰高度、戰場中央附近）。

**TLS 使用（`demoTLS`）**：機鼻 4° 內、3.6 km 內、400 m 外、目標視線角速度 < 0.09 rad/s（地面目標不看角速度）時切到 TLS；照射中機鼻持續對準目標的視線；照射中不換兵裝。EML／TLS 不需鎖定即可射擊（機鼻對準即可）。

**對地攻擊（`demoGround`，第 41.28 版）**：接近（目標上空約 2,400 m）→ 水平距離 7 km 內轉淺俯衝（15～20°），對準發射飛彈／雷射，近了機砲 → 離地 1,150 m 或 1.5 km 內拉起（雷射時 800 m），偏 35° 脫離 → 爬回再進入。實測最低離地約 460 m。

**量測工具**：`.tmp/aiw.ts`（模式 `air`／`gnd`／`ty`）統計 TLS 次數、對地擊毀、最低離地、鎖地面目標但仍有敵機的時間等。第 41.31 版兩場 900 s：鎖地面但有敵機的時間 0.7／1.7 s，都勝利（609／481 s）。

### 9.6 高度紀律

## 13. 繪製管線

這是整個專案最複雜、也最容易出問題的部分。

### 13.1 兩種雲模式
- **體積雲模式**（預設、高畫質）：Takram three-clouds＋three-atmosphere，經 `postprocessing` 的 EffectComposer。
- **一般立體雲模式**（`?clouds=classic` 或效能不足時自動退回）：自製的世界座標雲團、天空球、平的霧。

### 13.2 主迴圈的繪製順序（`main.ts` → `PostFX.render` → `VolumetricSky.render`）
1. `camCtl.update` → `view.update`（模擬狀態 → 物件）→ `shadows.update`。
2. `world.update`（天氣、雨、海浪時間、陽光）。
3. `world.renderReflection`／海面 `onBeforeRender` → **倒影**（鏡像攝影機，圖層 2，畫到 1024² 的線性色彩緩衝區）。
4. `post.setTravel`、`post.setWaves`（震波）、`post.setMask`（自機遮罩）。
5. `post.render(...)`：需要速度線、模糊或震波時先畫到暫存畫面，再一次全螢幕 pass；否則直接畫到畫面。
6. 體積雲模式時 `VolumetricSky.render(dt, overlays)`：
   1. 每 2 幀 `adopt()`：新物件歸類（半透明特效移到 FX 圖層、套 EARTH_CURVE、patch 特效材質、**光源開啟所有圖層**）。
   2. 讀 Takram 陰影圖給地面海面用（雲影，CLOUD_SH）。
   3. 近距離飛機（鏡頭前 4 km 內最近的 10 架＋自機）列為 overlays：在 composer 裡暫時隱藏，各分配一個量測圓片（probe）。
   4. `composer.render()`：場景（圖層 0）→ 雲 → 大氣 → 色調對應…（全部畫到暫存畫面，最後輸出到螢幕）。
   5. **`gl.flush()`**（第 41.29 版，見 §23）。
   6. 只寫深度補畫一次場景（統一的深度材質；跳過樹），讓之後的飛機與特效被地形正確遮擋。
   7. overlays 的飛機用自己的材質直接畫到畫面上（圖層 3，套上大氣霧色）。
   8. 每架 overlay：從雲的 overlay 圖量測鏡頭到機體之間的雲量（存成 1×1 貼圖並時間平滑），再用覆寫材質依距離蓋上雲霧（只在連線穿過雲層高度、1 km 內不作用、2.5 km 外全作用）。
   9. FX 圖層（火、煙、航跡、爆炸、曳光、雨）：依「鏡頭到特效的路徑在雲層高度內的比例 × 像素雲量」遮擋、遠處淡進霧色（FX_CLOUD）。
7. 鏡頭光暈、HUD。

### 13.3 為什麼這麼複雜
- 半透明特效不寫深度；留在後製管線裡的話，背景是天空的像素會被天空取代，特效消失 → 必須最後單獨畫。
- 自機與近處飛機穿雲時，如果在 composer 裡畫會被雲整個蓋白或閃動 → 單獨畫再依量測的雲量蓋霧。
- Takram 的雲是時間累積重建的，解析度一變就作廢 → 體積雲模式固定解析度（§23）。

### 13.4 線性輸出與色彩
- 倒影緩衝區是線性色彩：天空球在那一次輸出線性（`LINEAR_OUT`）。
- 主畫面 sRGB＋ACES（renderer.toneMapping = 4）；暫存畫面一律線性、不做色調對應 → 同一材質在兩邊畫會有兩個著色器版本（§23.4）。
- 煙、浪花、凝結雲、尾煙的受光：天氣時段影響最多 35%，其餘中性白光（黃昏不會整片土黃）。

### 13.5 後製（`PostFX.ts`）
單一全螢幕 pass：
- 速度線、邊緣模糊（依推力與速度）。
- **震波折射（第 41.28～41.29 版）**：取代原本的白色圓圈。每個震波 = 畫面中心、半徑（以畫面高為 1）、強度；S 形殼剖面（前緣往外推、後緣往內拉）＋沿圓周的強弱不均＋殼內細碎熱擾動；殼厚 `clamp(r×0.2, 0.005, 0.07)`、位移上限約畫面高 4.5%；半徑 `size×(15+95e)` m（e 為緩出）；強度 `(1-t)^1.5 × min(1,12t) × 0.9`。**自機遮罩**：後製拿不到深度，用自機在畫面上的範圍（中心＋半徑 11 m 的橢圓）把扭曲淡掉，否則自己的飛機會被扭爛。低畫質關閉。

## 14. 雲

### 14.1 體積雲的雲山設計（第 41.26～41.28 版，多次迭代）
使用者先要「雲層之上看到大山」，後來要「不要 100 個一樣的」、「不要一根根尖刺」、「高聳雲山可以存在，但不應該那麼多根尖尖的聚在一起」，並提供參考照片（零星、獨立的積雨雲塔，四周低矮積雲；雲上還有雲）。

最終做法（`patchCloudShaders` 改 Takram 的 `sampleWeather`）：
- 雲層範圍往上延伸到 `towerFt`（晴、黃昏 30,000 ft，陰 22,000 ft，雨 31,000 ft）；一般雲頂仍在 `topFt`（`uTopFrac`）。
- **雲塔場**：天氣圖用**固定的第 4 階 mip**（細節約 16 倍寬）、兩個不同大小與角度的取樣混合；**不能隨距離加 mipLevel**（否則遠處模糊過頭，雲塔全部消失 —— 實際踩過）。
- 門檻 `uTowerTh = 0.47`（可除錯調整）：以 Python 離線統計天氣圖，選出每 100×100 km 約數座、直徑數公里的獨立高峰。
- 雲塔 = `sqrt(smoothstep(th, th+0.08, v))`：側面陡、頂部寬圓（柱子／花椰菜狀），高度每座不同（另一張圖調變）；四周一圈 0.2 高的積雲丘；區域圖讓有些地方整片沒有雲塔。
- **雲塔所在一定要有雲**：把那裡的覆蓋率補上（`localWeather.x = max(..., cellK×…)`），否則晴天覆蓋率低、雲塔底下沒雲就看不到（實際踩過：做了半天天上沒有雲塔）。
- 雲頂起伏隨覆蓋率縮小：陰雨天是一整片較平的雲海（`0.3 + 0.55×smoothstep(0.4,0.8,coverage)`）。
- 天氣圖本身也打散：在原本取樣與另一個旋轉縮放取樣之間依約 600 km 一塊的雜訊漸變（原本約每 100 km 重複）。
- 只改主雲層 r 通道（`hfAdj.yzw` 保留原樣）。

### 14.2 上層雲（第 41.28 版）
- g 通道：主雲層之上約 1.5 km 零星較厚的高積雲（厚 600 m，`weatherExponent 2.4` 讓它保持破碎），陰天 ×0.7，雨天 0。
- b 通道：最高處（約 10.5 km）很薄、像紗的卷雲（densityScale 0.004、幾乎沒有立體形狀），雨天 ×0.5。
- 都不投影。

|---|---|---|---|---|---|

### 14.4 時間累積與閃動（Takram）
- Takram 時間重建模式下每像素每 16 幀重算一次；原本直接取代 → 靜止時也每 16 幀跳一次。改成和歷史混合（鏡頭靜止新樣本 12%、移動 30%；`upAlpha`）。
- 遠處細節用較低 mip（`mipLevelScale 2.5`）；時間濾波保留 96% 歷史、裁切放寬到 5 個標準差、9 點估計（`VARIANCE_9_SAMPLES`）。
- 光線步進每步 75 m（高）/100 m、步數上限 300，抵銷雲層變厚的運算量。

### 14.5 一般立體雲模式
世界座標的積雲團、雲海／雲底、卷雲；每團雲同時是一個體積，鏡頭真的在雲團裡才起霧；雲球上方永遠對齊世界上方；雲底是圓弧；逆光邊緣透光。

### 14.6 進雲與機身穿雲

- 機身穿雲：見 §13.2 的 overlay 量測。

## 15. 海面

- Three.js 官方 `Water`（真實鏡面倒影）；建立失敗或著色器編譯失敗時自動退回原始海面（`?sea=legacy`）。
- **倒影**：只畫天空、島、飛機、火光（煙、雨、淺水、地面單位、量測圓片不畫：`mirrorHide`）；倒影裡不畫太陽圓盤（改成碎亮的反光）；倒影扭曲量距離至少以 250 m 計、偏移上限 1.5%（否則會映出不存在的樹）。
- **倒影裡的飛機用自己的一份材質**（第 41.34 版，見 §23.4）。
- **長浪**：十四道深水波（波長 13～263 m、彼此不成整數倍；長浪方向集中、短浪散開），座標用大尺度雜訊扭曲；一群一群的浪；依「相鄰像素相位差」做頻寬限制（真正的濾波）；依波長在 2～23 km 外淡出。風浪依天氣（晴 1.0、陰 1.25、黃昏 0.9、雨 2.0）。
- **白浪**：只在「這一帶浪大且剛好是浪峰」的地方，稀疏不規則。
- **法線貼圖**：四層、各轉不同角度、大小錯開（103／167／1091／8907 m）、大尺度雜訊混合打散格子；**細浪兩層依像素涵蓋的貼圖大小淡出**（第 41.28 版，遠處斜看不再出現摩爾紋）。
- **海平線**：遠方淡進大氣霧色（最遠約九成），朦朧不是一條線。
- **拍岸浪花**：依離岸距離（逐像素高度換算）畫往岸推進的白浪（約 7.5 s 一道、相隔約 60 m）；貼岸 50～150 m 一圈翻騰白水；12～22 km 外淡出。
- **浪沖上沙灘**：水面以上 0～4.5 m，浪花線週期性沖上退回，下面一層薄海水、退浪留泡沫；沿岸時間高度各不同。**浪花線依「一個像素涵蓋的高度差」淡出**（第 41.30 版，0.35～0.9 m／像素），避免遠處閃爍。
- 為了讓浪沖得上沙灘：海岸附近陸地在畫面上只比水面高 1.5 m 平緩接進海（原本一律抬高 14 m）；海拔 8 m 以上仍 +14 m；離鏡頭越遠海岸整體上抬（最多 12 m）避免深度競爭。
- **逐像素海岸線**（第 41.13 版）：鏡頭 1.8 km 內，島嶼高度資料上傳成半浮點貼圖，雙三次 B-spline 取樣，低於浪花平面的地形像素丟掉露出海面；誤差約 1 m。
- **淺水**：把底下海面調亮的乘法混合，依地形網格算每點到最近陸地的距離。
- **貼海水花**：200 ft 以下機尾後方激起水霧，被空氣拖住留在原地，越低越快越濃；飛彈也有。
- 雲影：海面在雲影裡變深、沒有陽光反光。

## 17. 光照、天氣、雨、陰影、雲影

- **光照**：環境光 × 0.8、太陽直射 × 1.2，地形海面平地亮度補償回原本；晴天黃昏直射強，陰雨天以散射為主。
- **體積雲模式**：大氣透視 × 0.85；雲的天空補光 × 0.85、地面反光 0.45（雲的明暗分明）。
- **光源在所有圖層都有效**（第 41.34 版，見 §23.4）。
- **雨**：鏡頭周圍一個循環的立體空間（110×80×110 m），1,600 條（低畫質 700）線段；雨絲方向 = 「雨滴相對於飛機的速度」（= 下落速度 − 飛機速度向量，**用實際移動方向，不是機鼻**）；下落速度誇張化為 38 m/s（第 41.28 版，真實約 9 m/s 時 100 m/s 以上一律水平、看不出快慢）→ 慢速明顯斜下、高速趨近水平；雲層頂以上漸停；長度約 1/40 s 曝光。
- **影子**：太陽陰影貼圖只涵蓋玩家附近 360 m（編隊、艦艇甲板互相投影）；遠處每架飛機用正交攝影機沿太陽方向即時畫剪影（96×96），投到下方第一個面（雲頂、甲板、島、海面），越遠越淡、1.6 km 外消失。
- **雲影**（第 41.25 版）：體積雲模式直接讀 Takram 自己算的陰影圖（3 張 cascade，交界漸變）；地面與樹只減直射光（晴最深 78%、黃昏 70%、陰 40%、雨 20%）；海面變深、沒有反光；一般雲模式用雲團俯視烘焙覆蓋圖沿太陽投影。
- **低太陽**（第 41.28／41.30 版）：太陽高度 17° 以下雲影漸淡、4° 以下沒有；投影長度上限（`max(sun.y, 0.3)`）；取樣範圍 1.6 個陰影圖像素（邊緣柔和，避免每幀跟著鏡頭移動時閃）。
- **鏡頭光暈**：太陽被山、自己機身、雲擋住時淡掉；陰天很淡、雨天沒有。
- **環境反射**：目前天候的天空（含太陽）畫成預模糊的環境貼圖（PMREM），只在換天候時重算。

## 18. 特效

`render/Effects.ts`。原則：**專業素材優先、層層疊加、所有東西都要預熱**。

### 18.1 粒子系統
- `ParticleSystem`（Points）：位置、速度、壽命、大小、顏色、旋轉；煙由雜訊煙團貼圖（四種造型）或逐格動畫；煙受陽光（向陽亮背光暗）；火由白熱冷卻成橘、暗紅。
- 容量固定，滿了隨機覆蓋；死掉的與最後一個交換（swap-remove）。
- **每幀只上傳用到的部分**（`upRange`，`addUpdateRange`，第 41.29 版）。

### 18.2 爆炸（第 41.18／41.24／41.26／41.28 版）
- 素材：Unity Labs 以 Houdini 模擬、CC0 釋出的逐格動畫（Explosion02HD 主爆炸、Explosion00／01 小爆炸、FireBall01 火球核心、WispySmoke01 煙、Flame02 火焰）；相鄰兩格補間（原本一秒十格一頓一頓）；不取格子邊緣（避免出現線）；火焰提亮、黑煙提亮成深灰稍透明。
- 組成：火球核心 → 主爆炸 → 晚 0.05～0.3 s 的幾團小爆炸 → 火星 → 碎片 → 煙。閃光：兩盞預先建立的點光源輪流用（數量固定，不觸發重新編譯）。
- **空中爆炸的煙**（第 41.28 版，使用者：「黑煙持續太久；要逐漸下降——粒子出生點下降，不是煙往下飄」）：不留停在原地的一大坨煙；改成一個看不見的「殘骸」從爆炸點往下掉（越掉越快，最快 75 m/s，水平阻尼），沿途每 0.05 s 冒煙團（壽命 2.4～3.4 s），頭 1.5 s 帶火；約 3～4 s 結束。S ≥ 1.5 兩道。地面爆炸照舊。
- **碎片**：S ≥ 0.8 的空中爆炸都有（9 塊；S ≥ 1.5 16 塊），速度 40～110 m/s、75% 燒著，沿途每 4 m 拖煙＋較大較亮的火光。
- **火星**：55＋45S 根、速度 150＋90S、壽命 1.7 s；寬度 0.22 → 0.5 m、最小像素寬加大、亮度加強（「現在只看到一大坨爆炸貼圖」）。
- 地面海面爆炸：貼地推開的塵土（海面水花）、往上噴再落下的土石／水柱、往上竄的黑煙；動畫中心抬到地面上方。

### 18.3 凝結雲
- **翼尖彩帶**：渦流強度依每一側機翼各自的升力：拉桿兩側、滾轉只有上升那側（副翼升力差 ∝ 動壓）；高動壓降低門檻；低空高速潮濕平飛也有淡淡一縷；高空乾較難；低速沒有。約 430 kt 以上、過載六成才完整（參考 AC7／Project Wingman）。
- **機翼上方凝結雲**：錨點由模型找出機翼前緣（翼展 26%～80%，掛在可動主翼上）；約四成五最大過載起出現，High-G 最明顯；陰雨天較容易。
- **尾翼與鴨翼**（第 41.28 版）：每個舵面量出範圍、在中央表面上方掛噴發點（跟著舵面轉），同一濃度（垂尾 0.55、水平尾 0.75、鴨翼 0.95）。真實依據：尾翼本身也產生升力；垂尾泡在 LERX 渦流裡（F/A-18、F-16 大攻角常見）。
- **穿音速凝結錐**（Prandtl–Glauert）：約 0.93～1.05 馬赫、潮濕、低空時機身中段一圈錐形雲，不需拉桿。

### 18.4 其他

## 23. 效能與穩定性 Know-How

**這一章是最貴的經驗**。症狀常常是「每隔一段時間卡一下」，原因藏在瀏覽器的顯示卡程序或記憶體回收裡，在一般的逐函式計時裡看不到。

### 23.1 不要每幀 new 顯示卡資源（第 41.34 版的元凶）
- 症狀：約每 10～20 秒卡 0.2～0.7 秒、FPS 減半。
- 使用者的 Chrome Performance 錄製檔顯示：`MajorGC`（只 14～39 ms）之後，`CrGpuMain` 的 `GPUTask` 連續被佔住 57／219／616／390 ms。
- 原因：`GroundView.buildWake` 每幀 `geo.setAttribute('position', new THREE.Float32BufferAttribute(...))`（三艘船 × 4 = 每幀 12 個 WebGL 緩衝區），舊的沒 dispose；記憶體回收時一次刪掉上萬個 → 顯示卡程序卡住。
- 找法：在瀏覽器裡包住 `gl.createBuffer` 等函式計數每幀次數，再用 `new Error().stack` 找呼叫者（three 的 `WebGLAttributes.update`），再比對前後兩幀哪些物件的 attribute 物件換了。
- 修正：固定容量的 typed array＋重複使用的 BufferAttribute、`setDrawRange`、`addUpdateRange`；容量不夠才換更大的一組並**明確 `geometry.dispose()`**。實測 600 幀新建緩衝區 7,200 → 32。
- 原則：**任何每幀更新的幾何都要預先配置、只更新範圍**；需要換掉時一定 dispose，不要留給 GC。

### 23.2 體積雲之後 `gl.flush()`（第 41.29 版）
- 症狀：體積雲模式每隔零點幾秒有一格卡在「後面某個普通的 draw call」上 20～290 ms（GPU 實際每格只花約 6 ms，用 `EXT_disjoint_timer_query_webgl2` 量過）；關掉體積雲就完全沒有。
- 原因推測：Chrome 的顯示卡程序積了太多指令。
- 修正：`composer.render()` 之後 `renderer.getContext().flush()`。逐格量 1,800 格：卡頓 15～41 次 → 0 次。

### 23.3 著色器預熱要用「實際的管線」
- 第一次畫某種材質才編譯（ANGLE／D3D 可能要幾十～幾百毫秒）。
- 載入時（`warmContent`）把每種機體（我方／敵方塗裝）、飛彈、每種特效、場景所有物件（含隱藏）畫到一張 128² 的暫存畫面 → 但這只編譯「畫到暫存畫面」的版本。
- 實際上同一材質在不同地方畫會是不同的著色器：主畫面（sRGB＋ACES）vs 暫存畫面（線性、無色調對應）、有霧 vs 沒霧、體積雲模式的 EARTH_CURVE、FX 材質修補…
- 所以出擊後的頭 4 格（畫面還是全黑）再做一次：
  - 每種特效在**鏡頭前方** 1.5 km 放一次（在鏡頭後方時有些特效不會送出繪製、不會編譯 —— 火星就是），雷射三種落點、電磁砲、曳光彈都包含；放完立刻 `adopt()`。
  - **每一種飛機（機種＋陣營＋塗裝）**移到鏡頭前方、作為 overlays 走一次「近距離直接畫到畫面」與倒影。
  - 第 4 格清掉。
- 實測：第一次爆炸那格 142 → 11 ms；出擊後 0～50 秒新編譯 0 個（原本敵機第一次飛近時卡 0.2～3 秒）。
- 瀏覽器會自己快取編譯結果（依顯示卡、驅動）；`gpuSignature()` 偵測變更並在載入畫面說明這次會比較久。

### 23.4 three.js 的「著色器識別字串重組」
- three r170 每次畫一個物件都檢查材質狀態是否改變（霧物件、輸出色彩空間、色調對應、光源狀態版本…）；任何一項不同就呼叫 `getProgram` → 重組一個很長的識別字串（產生大量垃圾，增加 GC 壓力）。
- 踩到的三個來源：
  1. **光源的圖層**：光源依攝影機圖層過濾；各次繪製（圖層 0、3、FX、倒影圖層 2）看到的光源組合不同 → 光源狀態版本每次遞增 → 所有受光材質重組。修正：**所有光源 `layers.enableAll()`**（每幀 61 → 20 次）。
  2. **倒影 vs 主畫面**：同一個飛機材質輪流畫到倒影（線性、無色調）和主畫面（sRGB＋ACES）→ 每次都切換。修正：倒影時把飛機與飛彈的材質換成各自的複本（`WorldView.mirrorMat`，WeakMap 快取、原材質 version 改了才重做、每幀同步 opacity／color／emissive、ShaderMaterial 共用 uniforms）。
  3. **霧物件**：換 `scene.fog` 為 null 或另一個 Fog 物件也會觸發。修正：同一個霧物件只改參數（「沒有霧」= near 9e8、far 1e9）。
- 量測方法：暫時包住 `Material.prototype.customProgramCacheKey` 計數，記下 `renderer.properties.get(material)` 的 `lightsStateVersion`、`toneMapping`、`fog`。

### 23.5 動態解析度與雲品質
- 一般雲模式：幀率低於約 42 降 3D 解析度，回到 57 以上調回。
- **體積雲模式固定解析度**：雲是用前幾幀的畫面重建的，解析度一變累積全部作廢會閃（第 40 版在這裡每秒調整是閃動主因）。效能不足（< 40 fps 持續 5 s）時降雲品質（降了不升回），最低仍不行（< 26）才改用一般立體雲。

### 23.6 其他
- 粒子緩衝區只上傳用到的部分（§18.1）。
- HUD 光暈不用 `shadowBlur`。
- 樹：近處細緻（2.5 km 一塊）、遠處每島一次繪製的錐體（著色器隱藏已用細緻樹的區塊）。
- 倒影只畫必要的東西（`mirrorHide`）；倒影 1024²。
- 一般飛行單格約 5～7 ms（RTX 3070 Laptop）。
- **記憶體**：載入後 JS heap（含 ArrayBuffer）約 0.9～2 GB（大量解碼後的語音、地形、貼圖）；遊戲中每幀垃圾約 0.8～1.5 MB（three.js 繪製、HUD、模擬），仍有改善空間。

### 23.7 如何在使用者機器上量效能
- 內建瀏覽器分頁在背景時 `requestAnimationFrame` 會被節流 → 把 `requestAnimationFrame` 換成空函式，自己呼叫 `game.loop(t)` 推進（`__pump`），每幀後 `gl.finish()` 再計時。
- 逐子系統計時：包住 `hud.draw`、`post.render`、`sim.step`、`view.update`、`composer.render`…
- 顯示卡時間：`EXT_disjoint_timer_query_webgl2`（不能巢狀）。
- 分配量：`performance.memory.usedJSHeapSize`（包含 ArrayBuffer；有量化），在多幀之間累加正增量，並對照關掉某子系統（換成空函式）時的差。
- 最可靠的還是**請使用者錄 Chrome Performance**（F12 → Performance → 錄 20～30 s，存 .json），用 Python 解析 `traceEvents`：找 `CrRendererMain` 的長 `RunTask`、`FireAnimationFrame` 的間隔、`MajorGC`、`CrGpuMain` 的長 `GPUTask`。

| F/A-18 噴嘴跟尾翼擺 | 模型切舵面時噴嘴被分進水平尾翼 | 載入時把轉軸內側 0.5 m 以上的三角形留在機身 |

## 25. 開發、測試與交付流程

### 25.1 交付規則（使用者規定）
1. **一律用繁體中文溝通**。
2. 每次交付改 `src/version.ts`。
3. `ACCEPTANCE.md` 加一節（插在上一版的 `### 41.xx` 之前）：做了什麼、怎麼驗證、已知問題。
4. Git commit，訊息結尾加：
   ```
   Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
   Claude-Session: https://claude.ai/code/session_...
   ```
5. 打包 zip：拆檔版的 `index.html`＋`assets/`＋`sound/sound_pack.bin`＋本次改過的原始碼（排除 `dist/`、`.tmp/`）。使用者說**不用每版都包，最終版本包一個就好**。
6. 用 SendUserFile 交付，再用 `device_commit_files`（帶 fileUuid；大檔用 stagedPath 會失敗）寫進使用者的遊戲資料夾。
7. **交付前在使用者的機器上截圖驗證**（「記得好好檢查，不要交給我有問題的東西」）；用專業工具與網路資源，不手刻；誠實說明哪些驗證了、哪些沒有。

### 25.2 測試
- `npm run typecheck`、`npm run test:story`（必須全過）。
- `npm test`：撞地 0、相撞 0、無 NaN 三項要過；「多數戰鬥在 15 分鐘內分出勝負」從第 41.24 版前後就常不過（王牌／解放後的 Tyrant 活到時限），屬已知問題。
- AI 量測：`.tmp/aiw.ts`（esbuild 打包成 cjs 跑）、`.tmp/stab.ts`（姿態穩定度統計）。
- 天氣圖離線統計：Python 讀 `assets/clouds/local_weather.png`，模擬著色器的取樣與門檻、`scipy.ndimage.label` 數雲塔數量與大小。

### 25.3 在使用者機器上驗證
- 測試版：`/home/claude/tools/relsync.sh`（建置拆檔版 → `_dev/index.html` 加 `<base href="../">`，新的 assets 寫到根目錄 `assets/`）→ `device_commit_files` → 內建瀏覽器開 `localhost:8000/_dev/index.html?r=N`。
- 用 JS 控制：`window.__game`（主物件）、`launch()`、`setDemo()`、`cheats.freeCam`、`fc.pos/yaw/pitch`、`fx.explosion(P, size)`、`screens.show('preflight')`、`roster.settings.weather`、`vol.towerTh.value`（雲塔門檻）。
- 背景分頁節流：換掉 `requestAnimationFrame`，自己 `loop(t)`；等載入完成要檢查畫面文字沒有「載入中／準備」（`screens.current === 'menu'` 在載入中就成立）。
- 視窗大小：`resize_window` 1600×800（18:9）；手機觸控模擬用寬度 < 768（例如 740×360），會模擬觸控點與 `pointer: coarse`。
- 截圖前要等真正的一格畫出來（背景分頁時截圖可能是舊的）。
- 測完把視窗大小還原成 desktop。
