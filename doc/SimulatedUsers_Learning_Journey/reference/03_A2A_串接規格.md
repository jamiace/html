# A2A Agent-to-Agent：讓其他代理使用模擬學習者方法

## 必須先說清楚

A2A 不會將這份方法「直接訓練進所有 AI Agent」；它負責跨代理的發現、呼叫、任務與結果傳遞。讓代理學會方法的媒介是 `02_交給AI的技能規範.md`、輸入/輸出契約、測試案例與每次執行回饋。

## 三個 Agent，各司其職

**Persona Designer**（人物設計）
- 接收產品目標、範圍、測試模式。
- 交付人物設定、狀態模型、行為規則、假設清單。
- 不操作正式系統。

**Scenario Runner**（情境執行）
- 接收經批准的人物設定、事件規則、授權測試環境。
- 由排程器和瀏覽器/API 工具實際執行；執行引擎依規則決策，不應每一步都靠 LLM 臨場編故事。
- 交付事件記錄、截圖、錯誤和可重現步驟。

**Evidence Reviewer**（證據驗證）
- 對照測試目標、行為模式與真實系統紀錄。
- 對功能測試給出通過／失敗／未驗證；對行為模擬提供假設下的觀察。
- 一旦發現 coverage 強制補場，禁止產出「真人留存預測」。

## 基本協作順序

1. 主代理向 Persona Designer 傳送 `design_personas` 任務。
2. 取得人物與規則後，由人員或可重現的規則檢查器驗收。
3. 主代理向 Scenario Runner 傳送 `execute_scenario`，並指定 `mode`。
4. Runner 交付 `events.jsonl`、可重現參數、測試報告。
5. 主代理向 Evidence Reviewer 傳送 `review_evidence`。
6. Reviewer 交付已證實結果、模擬觀察、限制及下一輪調整。

## A2A 發送什麼？

A2A 的 Message / Task 承載任務、狀態與 Artifact；文件 `04_任務輸入範例.json` 是**應用層的任務資料**，不是一個可以直接 POST 的完整 A2A 協定封包。實作時請用官方 SDK 的 DataPart / Artifact 將這份 JSON 傳遞。

Agent Card 用來公告能力與介面，見 `05_AgentCard_範例.json`。其中 localhost 端點是**範例占位**，沒有建立或啟動任何服務。需要部署真正的 executor、task store、認證與網路端點後才可互通。

## 最低操作守則

- 要求明確 `environment`，正式站若涉及非測試用戶、付款、資料修改，須有人員授權。
- 每個事件帶 `synthetic=true`，測試帳號與真人資料隔離。
- `mode=coverage` 與 `mode=behavior` 不可混用統計。
- `seed`、模型版本、規則版本、產生的事件都必須可以追溯。
- 最終驗證指標應是程式／系統真的回傳的狀態，不是代理自行聲稱成功。
- 沒有真人樣本及外部校準，不得將模擬分布當成市場分布。

目前 A2A 1.0 Agent Card 使用 `supportedInterfaces`；請以當時官方 SDK 與規格檢查欄位。若不需要跨組織或跨框架 Agent，單一服務使用函式呼叫與佇列，往往比部署完整 A2A 更簡單。
