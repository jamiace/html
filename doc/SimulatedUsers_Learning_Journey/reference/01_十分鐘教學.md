# 十分鐘教學：如何設計會「生活」的模擬學習者

## 一、先不要急著設計三十個人

先問自己：「這次要檢查什麼？」例如：
- 學習功能能否對不同程度的人正確給題？
- 有人中途離開再回來，是否能正確續接？
- 當使用者一直答錯，系統有沒有記錄、提供適當回饋？
- 在不同語言、裝置與作息下，登入、存檔、畫面是否正常？

**不要把『驗證功能』和『測量真人會不會留下來』當成同一件事。**

## 二、先做三個人，比一口氣創造三十個更有用

每人只填七項：

| 項目 | 要填什麼 |
|---|---|
| 身分／情境 | 小學生、忙碌成人、新使用者…… |
| 目前能力 | 對應任務的熟練程度；不要只填年齡 |
| 想完成的事 | 例如照顧貓、完成每日任務、聽音樂 |
| 喜歡／討厭 | 例如喜歡短任務、討厭長篇閱讀 |
| 時間條件 | 什麼時候有空、通常一次能用多久 |
| 遇到挫折時 | 會繼續、改做別的、還是離開 |
| 可能改變的狀態 | 興趣、熟悉度、疲倦、記憶、習慣 |

**示範人物 A（短頻多次）**：通勤族，平日只有零碎的三到五分鐘，喜歡快速任務，遇到一段太長的操作可能直接離開。

**示範人物 B（好奇但易膩）**：新使用者，前兩天興趣很高；如果重複活動沒有新意，之後會降低啟動意願。

**示範人物 C（目標導向）**：只想把寵物照顧好，可以做題換食物，也可以花遊戲幣購買；不是每次都會選擇學習。

> 以上三個是教學用的簡化例子，不是聲稱所有真實玩家都會這樣行為。

## 三、設計「事情發生後，人會怎樣改變」

比起固定規定「每天下午七點登入」，更有用的是寫出因果規則。

例：
1. 今天有空，而且對遊戲還有興趣，才有機會登入。
2. 登入後先看現在最在乎的事，不是保證先做學習題。
3. 選了學習題，如果很順利，熟悉度／信心可能上升。
4. 如果連錯幾題，挫折可能增加，下次可能轉去養貓或離開。
5. 明天的選擇要受到今天經驗影響，不是每天重新擲同一顆骰子。

需要時可用隨機抽樣，但抽樣的機率應受到人物狀態影響；每次執行必須記錄亂數種子，才能重現。

## 四、明確分成兩種測試模式

### 模式 A：功能覆蓋（Coverage）
目的：讓所有功能、題型、例外流程都有人走過。

可以強制排程：今天一定要測登入、重新登入、題目放棄、跨日、語系切換。

輸出：通過率、失敗畫面、日誌、可重現步驟。

**禁止將這種強制執行的數據用來推論自然留存、使用時間或動機。**

### 模式 B：行為模擬（Behavior）
目的：觀察在指定假設下，不同類型人物可能如何選擇、流失、回流。

允許一整天不登入、拒絕做題、失敗後離開，不得為了後台圖表好看而補場次。

輸出：人物狀態變化、選擇路徑、模型假設、敏感度分析。

**禁止宣稱模擬結果就是市場真相。** 真人數據用來後續校準，而不是拿模擬代替真人。

## 五、每天保留這五類紀錄

- 發生什麼：登入、答題、離開、購買、休眠。
- 為什麼選：當下目標、時間限制、喜好或觸發事件。
- 人物改變：習慣、動機、熟悉度、記憶等。
- 系統回應：畫面、API、結果、錯誤。
- 可重現證據：人物 ID、模型版本、時間、亂數種子、操作紀錄。

## 六、什麼時候算成功？

功能覆蓋成功：預定流程有走到，錯誤能夠重現和定位。

行為模擬成功：不同設定能產生合理且可說明的差異；調整一個參數時，結果的變化符合事先提出的假設。**這仍不能證明它和真實人類相同。**

## 最小練習

用一個大家熟悉的系統，設計三位使用者，跑七天即可。先不用 AI 自主操作瀏覽器；拿紙筆或試算表記錄每天的狀態、選擇與結果，就已經能學會這套方法的核心。
