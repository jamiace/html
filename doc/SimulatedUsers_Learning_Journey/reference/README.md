# 模擬學習者／使用者方法包（入門版＋AI Agent 版）

這是一套 **設計方法與代理協作規格**，不是已部署的 A2A 伺服器，也不是 Purr Cozy 原本的模擬程式原始碼。

## 這套方法要解決什麼

把「虛構一個使用者」提升成「建立一個會受到動機、能力、時間、習慣、記憶、產品回饋影響，且會隨時間改變的測試者」。

- 人讀：`01_十分鐘教學.md`，按步驟設計 3 個模擬使用者。
- 任何聊天式 AI 讀：`02_交給AI的技能規範.md`，可直接貼給代理當任務規則。
- 需要 A2A Agent-to-Agent 的研發人員讀：`03_A2A_串接規格.md`，搭配 `04_任務輸入範例.json`、`05_AgentCard_範例.json`。

## 一個不能忽略的結論

**功能覆蓋**和**行為模擬**必須分流。為了確保每人每天執行固定次數而強制補量，適合用來覆蓋流程，不能同時拿這組結果當成自然留存率。

## 資料依據與版本差異

整理自本次提供的：
1. `試玩計畫-30位測試帳號.md`（初始設計，列出 10 種黏著類型與 30 個角色）
2. `Design_30test_players.html`（較早的設計展示，使用 7 類上線習慣與全時段補位規劃）
3. `purrcozy-report-300test-plan-new.html`（11/21 報告，指出後期 coverage 模式改變了自然登入與流失行為）

三者是**不同階段的設計與結果**，不可硬把 7 類與 10 類合併成一份「同時存在」的最新設定。本包保留可共用的原則，並把實際發現的限制放進測試規範。

## A2A 的定位

A2A 是讓不同 AI Agent 互相發現、委派工作、交換狀態與產物的通訊協定；它**不是把知識直接寫進其他模型權重的訓練協定**。要讓其他 AI 使用這套方法，應先提供清楚的技能說明／測試契約，再透過 A2A 把任務交給對應的專業 Agent。

官方規格：https://a2a-protocol.org/latest/specification/
官方 Python SDK：https://github.com/a2aproject/a2a-python

## 結果可以說明什麼

- 可以：驗證操作流程、事件紀錄、跨裝置測試、錯誤復現、分析系統能否辨別不同使用者類型。
- 不可以：僅憑模擬結果宣稱真實使用者的留存、偏好、學習成效與市場規模。
