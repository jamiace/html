SIMULATED USERS / FIELD GUIDE

當不同 AI Agent 開始合作。

技術延伸：A2A 的職責分工、協定定位與 Agent Card 範例

A2A（Agent-to-Agent）是讓不同代理互相委派任務、交換狀態與交付成果的協定；它不會直接把這份方法「教進」模型權重。真正讓代理遵循方法的，是上一頁的技能規格與任務契約。

最小分工

三個代理，分別做好三件事

1

Persona Designer｜人物與用途

接收同事的專業描述，提出跨領域用途、設計人物、標明假設；不直接操作正式系統。

2

Scenario Runner｜有紀錄地執行

在授權的測試環境裡依規則操作，保留截圖、事件紀錄、規則版本與可重現步驟。

3

Evidence Reviewer｜看證據而不是聽故事

把實際系統回應與模擬觀察分開，指出哪些流程真的驗證過、哪些仍需真人。

最容易搞混的事

Skill：讓代理知道要遵守什麼方法、應該輸出什麼。

A2A：讓不同代理有一致的方式互相傳遞任務、狀態與成果。

執行器：真正負責瀏覽器、API、排程與事件記錄。

如果只需要一個聊天式 AI 協助設計三位模擬人物，完全沒有必要先架設完整的 A2A。

先把一個小實驗做對，再決定是否值得拆成多代理。

A2A Agent Card 1.0：可編輯的示意檔

依 2026 年 11 月查核的官方 1.0 規格，supportedInterfaces[] 承載每個端點的 url、protocolBinding 與 protocolVersion。

{
  "name": "Simulated User Designer",
  "description": "Designs stateful personas, cross-domain transfer ideas, and reproducible scenario plans. Does not equate synthetic data with real-user evidence.",
  "version": "0.2.0",
  "supportedInterfaces": [
    {
      "url": "http://127.0.0.1:8000/a2a",
      "protocolBinding": "JSONRPC",
      "protocolVersion": "1.0"
    }
  ],
  "capabilities": {
    "streaming": false,
    "pushNotifications": false
  },
  "defaultInputModes": [
    "text/plain",
    "application/json"
  ],
  "defaultOutputModes": [
    "text/plain",
    "application/json"
  ],
  "skills": [
    {
      "id": "design_personas",
      "name": "Design simulated users",
      "description": "Create domain-transfer ideas, simulated user profiles, behavioral policies and evidence-aware experiments.",
      "tags": [
        "simulation",
        "user-experience",
        "quality-assurance",
        "education"
      ]
    }
  ]
}

A2A 任務與應用層資料的差別

example_request.json 描述的是你的研究需求，不是能直接傳給 A2A 端點的完整協定封包。實作時要由 SDK 或客戶端將資料包裝成符合協定的 Message / Part，再處理 Task 的生命週期與回傳產物。
